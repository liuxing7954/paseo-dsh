# 国际化（i18n）

这个仓库是双语项目，不是"先写中文以后再翻译"。**任何新增的用户可见文案，都要同时有英文和
简体中文两份**，并且跟随 Paseo 的应用语言显示，而不是写死一种语言。

用户指的是阅读者：英文读者不该在英文界面里看到「思考」「运行中」，中文读者也不该在中文界面里
看到 `Thought` / `Running`。

---

## 1. 三种文案，三种做法

先判断这段文案最终由谁绘制，再决定用哪种方式。搞错这一层是最常见的 bug。

| 文案出现在哪 | 谁绘制 | 做法 |
|---|---|---|
| 插件自己的 React UI（时间线行、抽屉、设置页、toast、无障碍标签） | 插件 | 进 `client/locales/*.json`，组件里用 `useTranslation(messages).t(...)` |
| Paseo 宿主绘制的**持久标签**（设置页标题、命令中心标题、斜杠命令描述、按钮标题、主题名） | 宿主 | 用 `messages.message("key")` 传 `PluginText`，宿主按应用语言渲染，**不要**提前 `t()` 掉 |
| daemon 写、宿主原样显示的**一句话**（时间线 notification、preset 选项标签、错误摘要） | 宿主，内容是 daemon 写的 | 两种语言都写上：`Preset switch failed / 切换预设失败：…` |
| daemon 返回的**结构化失败**（RPC 输出里的原因） | 客户端翻译 | 传错误码（枚举）+ 原始细节（`errorCode` + `errorDetail`），客户端出词 |

`t()` 的结果是快照：语言切换不会让它重算。所以 `client.i18n.t(...)` / `t(...)` 只用于
**当次渲染 / 当次回调**，任何注册给宿主的标签都必须用 `messages.message(key)`。

**语言覆盖**：设置页的「界面语言」默认 `auto`（跟随宿主）。选择 `English` 或 `简体中文`
后，只覆盖本插件自己绘制的界面；`useTranslation` 会立即重渲染，宿主持有的持久标签
（设置页入口标题等）仍是注册时的快照，始终跟随宿主/设备语言。覆盖值按 host 保存，
跟随该 host 同步。

## 2. 目录与文件

```
client/locales/en.json      ← 键的唯一来源（英文），必须有
client/locales/zh-CN.json   ← 可以少键，少的那些回落到英文
client/messages.ts          ← defineTranslations({ resources: { en, "zh-CN": zhCN } })
```

- 英文是键的权威：**新增键先加 `en.json`**，再补 `zh-CN.json`。
- `zh-CN` 允许缺键；缺了就是英文，不算错误。
- 键用英文语义化小驼峰，按界面分组：`timeline.tool.read`、`timeline.status.failed`、
  `streamStats.firstToken`、`settings.field.rowMarginY.label`。
- 不要拼字符串造句子（`t("a") + " " + t("b")`），也不要为了省事把变量拼进 `t()` 的键名里以外
  的地方——需要变量就用插值。

## 3. 追加一门语言

运行时的语言集合就是 `client/messages.ts` 里 `resources` 的键集合，Paseo 按 app 语言在里面挑
最近的匹配。加语言是两个注册点 + 一份文案 + 一份插件页正文：

1. **加文案**：`client/locales/<tag>.json`，把 `en.json` 整个拷过去再逐条翻。
   文件名必须是 canonical 标签（`ja`、`ko`、`zh-TW`、`pt-BR`），**不能**写 `zh-cn`、`ja-JP-u-ca`。
   可以少键（回落英文），但不能多键、不能改 `{{占位符}}` 名字。
2. **注册到运行时**：`client/messages.ts` 里 import 并加进 `resources`：

   ```ts
   import ja from "./locales/ja.json";
   export const messages = defineTranslations({ resources: { en, "zh-CN": zhCN, ja } });
   ```

3. **注册到目录页**：`paseo-plugin.json` 的 `translations.<tag>` 里补 `name` / `description`
   （这个字段只有 registry 读，Paseo 运行时不读）。
4. **插件页正文**：新增 `OVERVIEW.<tag>.md`，内容与 `OVERVIEW.md` 对齐。它已在 `package.json`
   的 `files` 里以 `OVERVIEW.md` + `OVERVIEW.zh-CN.md` 形式列出，再加语言记得一起补。
5. **验证**：`npx tsc --noEmit && node scripts/check-locales.mjs`。检查脚本自动扫
   `client/locales/*.json`，加语言不需要改脚本；它会拦下非 canonical 文件名、凭空多出来的键、
   占位符不一致。

6. **语言覆盖设置**：如果新语言要出现在插件的「界面语言」设置里，还要同步
   `shared/settings.ts` 的 `languageSettings` enum、`client/settings-screen.tsx` 的
   `LANGUAGE_OPTIONS` 和 `client/i18n.ts` 的 `catalogFor`（它目前只区分中文和英文）。

不需要改的：组件代码（`t()` 与 `messages.message()` 与语言无关）、服务端、桥接。
**不要**在 `server/` 里判断语言——它不知道也不该知道。

## 4. 插值与复数

- 插值写 `{{name}}`，两种语言的占位符名字**必须完全一致**，否则插件加载时会被拒绝。
- 复数键以 `_one` / `_other`（以及 `_few` / `_many` / `_zero`）结尾，调用时传 `count`：
  `t("streamStats.tools", { count: n })`。中文只需要 `_other`。
- 数字、日期、单位不要自己格式化：能交给 `Intl` 的就交给 `Intl`，或让两种语言各自决定写法。
  行宽敏感的紧凑行可以退一步用语言中立的写法（例如任务行用 `2/5`，动词单独翻译）。

## 5. 硬性要求（提交前自查）

1. **不留裸中文、也不留裸英文**在插件 UI 里。凡是 `Text` / `accessibilityLabel` / toast 的字符串，
   要么来自 `t()`，要么是语言中立的数据（文件名、命令、URL、工具名）。
2. **daemon 不许猜语言**：`server/` 与 `dsh-bridge/` 里不要按语言分支，也不要往 RPC 输出里塞句子。
   返回码 + 客户端翻译；宿主必须原样显示的那一两句写成中英并列。
3. **注册给宿主的标签用 `messages.message(key)`**，不要用 `t(key)` 的结果（语言切换后不会更新）。
4. **新工具 = 新行 = 新键**：加一个工具类型，就在两份 locale 里补动词，并保证未知工具落到通用行
   （`Wrench` + 工具名），不能因为不认识就退回宿主样式或干脆不显示。
5. **改完跑检查**：

   ```bash
   cd paseo-plugin
   npx tsc --noEmit
   node scripts/check-locales.mjs     # 键、占位符、复数、孤儿键
   ```

   `npm test` 和 `npm publish` 的 `prepack` 也会跑 `check-locales`。

---

## 6. 版本要求

运行时翻译 API 与 `client.i18n` 需要 **Paseo ≥ 0.13.0**（插件翻译 API 首发版本）。
`paseo-plugin.json` 的 `requirements.paseo` 与 `package.json` 的 `@getpaseo/plugin`
peer 依赖都写 `>=0.13.0`；下调之前先确认宿主真的提供 `useTranslation`，否则 client entry 会在
加载时崩掉。

---

## 7. 发布面（README、OVERVIEW、清单）

- `README.md`（中文）+ `README.en.md`（英文），两份内容对齐；changelog 两边各加一行。
  再加语言时同样成对新增 `README.<tag>.md`，不要只改一边。
- `OVERVIEW.md` 是**英文**的插件页正文，`OVERVIEW.zh-CN.md` 是同内容的简体中文版；
  两份都随版本更新，且都不写安装命令。
- `paseo-plugin.json` 的 `name` / `description` 写英文，`translations.<tag>` 里放其他语言；
  清单里各字段可单缺，缺了显示英文。
- 包内 CLI（`bin/`、`tools/`、`harness/`）输出保持英文即可，它不是应用内文案。
